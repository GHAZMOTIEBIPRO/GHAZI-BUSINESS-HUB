# CLAUDE CODE — EXECUTION BRIEF / GHAZI BUSINESS HUB

أنت فريق تنفيذي لبناء منصة سعودية **موحدة** لمقاولي التشطيبات والصيانة، تتضمن رادار فرص المشاريع ومتجر أدوات Excel.

## نقطة البداية

أمامك ملف ZIP يحتوي نسخة تجريبية HTML/CSS/JS تعمل محليًا، وقوالب Excel فعلية (4 ملفات) وREADME. اقرأ الملفات ونفذ مواصفاتها، لكن لا تخلط هذا المشروع مع GHAZIBOT الخاص بالأسهم.

## الأدوار المطلوب تفعيلها في العمل

- مدير منتج B2B مقاولات في السعودية
- محلل تنافسي ومصادر رسمية
- مهندس معماري SaaS وقاعدة بيانات
- مهندس أمن وخصوصية PDPL
- خبير حصر وتسعير أعمال تشطيبات
- محاسب تكاليف ومراقبة مشاريع
- مهندس تجربة مستخدم RTL متجاوبة
- مسؤول امتثال للتجارة الإلكترونية والفوترة
- خبير QA واختبار أمني
- مدير نمو وتسويق تجريبي

## خطة التنفيذ الملزمة

### 0. تدقيق ما تم تسليمه
- شغّل الموقع محليًا وصوّر الواجهة على الهاتف والكمبيوتر.
- اختبر كل الفلاتر والنماذج وتحميل XLSX والحاسبة والحفظ والتصدير.
- افحص أوراق Excel والصيغ والأخطاء الحسابية والأمنية.
- اكتب جدولًا: موجود / اختُبر / يحتاج إصلاح / غير مبني.

### 1. تأسيس مشروع مستقل
- استخدم مستودع GitHub مستقلًا باسم `GHAZI-BUSINESS-HUB` أو اسم متاح مماثل (لا تنشئه أو تفتح خدمة مدفوعة دون إذن المالك).
- احتفظ بالبيانات الأصلية والمصدر وفهرس الحقوق.
- أنشئ بيئة staging منفصلة عن الإنتاج مع CI.
- نقل واجهة النموذج إلى تطبيق احترافي قابل للاستضافة، دون نسخ React غير ضروري قبل التقييم.

### 2. نواة الفرص
- احفظ فرصة بمصدر وعنوان ورابط وتاريخ نشر ونوع وتخصص ومدينة وحالة تدقيق.
- حالات الفرص مستقلة: OPPORTUNITY_LEAD, OPEN_TENDER, AWARDED_PROJECT, SUBCONTRACT_CONFIRMED, CLOSED, UNKNOWN.
- لا تنشر SUBCONTRACT_CONFIRMED إلا عند وجود دليل مباشر من الجهة المسؤولة أو مصدر موثوق يصرح بذلك.
- لكل جهة اتصال: الاسم المهني، المسمى، قناة العمل المنشورة، عنوان المصدر، تاريخ تأكيد، وصلاحية عرضها.
- تصميم قائمة انتظار مراجعة بشرية، ومهلة تحديث/انتهاء صلاحية، وزر بلاغ عن خطأ.
- احترم robots وAPI policies وحقوق النسخ؛ لا تستخدم scrapers لمواقع مغلقة أو تتطلب حسابًا/دفعًا.

### 3. متجر رقمـي واحد
- منتج، نسخة، ملف أصلي، سعر شامل/غير شامل ضريبة وفق إعدادات واضحة، ترخيص استخدام، صورة معاينة، حد تنزيلات، فاتورة وإلغاء.
- بوابة دفع sandbox فقط أولًا، بطلب تحقق signatures وidempotency وعدم كشف أسرار مفاتيح الدفع.
- اختبارات duplicate webhooks، expired download link، refund، concurrent purchase، user ownership.
- إخفاء الروابط الأصلية للملفات المدفوعة؛ استخدم object storage خاصًا وروابط قصيرة الصلاحية.
- يسمح بجمع اشتراك الرادار ومشتريات المنتجات بحساب واحد.

### 4. النشر التجاري بعد الإذن
- مراجعة السجل/وثيقة العمل الحر والحساب البنكي وتوثيق المتجر في منصة الأعمال.
- مراجعة الخصوصية وPDPL والعروض والأسعار وسياسة استرداد المنتجات الرقمية.
- التحقق من ضريبة القيمة المضافة والفوترة الإلكترونية عند انطباقها.
- اختبار استعادة نسخة احتياطية، وحماية الملفات، وفصل المستخدمين.
- لا تضع أسماء شركات أو أرقام مسؤولين أو فرص فعليّة دون مصادر موافق عليها وإسناد واضح.

## معايير نجاح المنتج
- ظهور الحقول الناقصة بوضوح؛ لا تزوير جهة اتصال أو حالة مشروع.
- بحث حسب التخصص والمدينة ونوع الفرصة، ونتائج تتضمن المصدر وتاريخ التأكد.
- مستخدم A لا يرى/يعدل بيانات مستخدم B (اختبارات IDOR).
- المستخدم يدفع في Sandbox ويحصل على إذن تحميل ملفه فقط.
- ملفات Excel لا تحتوي على أسعار مواد مخترعة أو صيغ منكسرة.
- جميع وظائف الموقع قابلة للتجربة على جوال 390px وسطح مكتب 1440px.
- لا تُسمَّى المنصة جاهزة للبيع حتى يكتمل اختبار الأمان والحقوق والدفع والاستضافة.

## أسلوب التقدم

نفّذ على دفعات صغيرة مع اختبارات. افتح Pull Request ومسودة مراجعة، ولا تنشر إنتاجًا أو تحصّل مالًا حقيقيًا أو تدمج تغييرات دون موافقة. كل تقرير يسرد بالضبط: CODED, TESTED, CI GREEN, MERGED, RUNTIME VERIFIED.
