# منصة غازي للأعمال | GHAZI Business Hub

نسخة أولية **تفاعلية تعمل محليًا** لموقع سعودي يجمع رادار فرص المقاولات ومتجر أدوات المقاول الرقمية في واجهة واحدة.

**الحالة: MVP Offline Demo / NOT DEPLOYED / NO LIVE PAYMENTS / NO AUTOMATED OPPORTUNITY FEED.**

## البدء

افتح `index.html` بمتصفح حديث. تعمل الواجهة دون خادم؛ روابط القنوات الرسمية تحتاج إنترنت. من المفضل تجربة المجلد عبر HTTP محليًا:

```bash
cd ghazi_business_hub
python -m http.server 8766
# http://localhost:8766
```

الموقع باللغة العربية بالكامل ومتجاوب مع الجوال. لا يحتاج تثبيت مكتبات.

### ما يعمل فعلًا

- واجهة تنقل موحدة لخمس صفحات (الرئيسية، الفرص، المتجر، الحاسبة، المساحة الشخصية).
- دليل لثلاث قنوات رسمية أو معلنة لبحث المقاول، بلا ادعاء وجود فرصة فردية نشطة.
- إدخال فرصة يدويًا مع رابط مصدر HTTPS ومدينة وتخصص وجهة وملاحظات وحالة مراجعة.
- فلاتر بحث وحالة وتخصص ومدينة، ومؤشر تطابق تخصصي *محلي* استرشادي غير مدعوم بتعلم آلي.
- حفظ فرص وتخصصات في متصفح المستخدم فقط؛ تصدير JSON ومسح التجربة.
- متجر يحتوي أربعة ملفات Excel بصيغ حسابية فعلية، وروابط تنزيل وحزمة ZIP.
- حاسبة سعر عرض تستخدم الربح والمصاريف العامة كنسب من سعر البيع قبل ضريبة القيمة المضافة.

### ما **لا** يعمل بعد

- لا توجد قاعدة بيانات سحابية، حسابات، أدوار، أو نظام إدارة فعال للمنصة متعدد المستخدمين.
- لا يوجد دفع حقيقي، اشتراك، ترخيص تنزيل تلقائي، إيصال أو فاتورة إلكترونية.
- لا يوجد اتصال مباشر بمنصات اعتماد أو مقاول، ولا كشط بيانات، ولا فرص باطن مثبتة ومدخلة من فرق تحقق.
- التخزين في localStorage، وهو مناسب للتجربة فقط، وليس لحفظ بيانات العملاء أو الملفات السرية.
- الفئات والأسعار في المتجر افتراضية لا تمثل عرض بيع أو طلب دفع.
- لا يوجد ضمان بأن قنوات المصادر الخارجية تسمح بإعادة نشر أو استخراج بياناتها آليًا.

## وحدات النسخة التجارية المقترحة

1. **رادار الفرص:** دليل مصادر مصرح بها، فريق تحقق، تصنيف الفرصة (مناقصة/ترسية/مشروع جارٍ/باطن مؤكدة)، تاريخ آخر تحقق، زر مصدر، تطابق نطاق وتخصص، وإشعارات.
2. **ملف المقاول:** المدينة، الأنشطة، القدرة المالية والفنية، نطاق قيمة العقد، ملف الأعمال، إشعارات مدفوعة.
3. **متجر الملفات الرقمية:** كتالوج، عينات، دفع، تنزيلات موقعة زمنياً، تحديثات ورخصة مستخدم، سياسة استرجاع ملائمة للمنتجات الرقمية.
4. **أدوات مجانية جاذبة:** حاسبة تسعير وتكلفة عمالة، وقوالب بسيطة لجلب العملاء.
5. **لوحة الإدارة:** حقول مصدر موثق، مراجعة مزدوجة، طلب تصحيح، سجل تغييرات، إدارة المنتجات والأسعار والفواتير.
6. **قاعدة بيانات واحدة للعملاء والفوترة:** اشتراك رادار وشراء منتج مستقل من حساب موحد.

## سياسة مصدر الفرصة

كل سجل إنتاجي يجب أن يحتوي على: مصدر أصلي، رابط، نوعه، تاريخ النشر، وقت آخر مراجعة، حالة التقديم، التصنيف، المنطقة، تخصص الأعمال، صاحب المشروع (إن ثبت)، المقاول الرئيسي (إن ثبت)، وسيلة تواصل أعمال منشورة ومتحقق منها (إن كانت مصرحًا بإعادة نشرها)، اسم المدقق، وتاريخ انتهاء صلاحية المراجعة.

**لا تساوِ بين منافسة مفتوحة وبين فرصة باطن مؤكدة.** وجود مناقصة حكومية لا يعني مباشرة وجود مقاول رئيسي كسب المشروع. بيانات الترسية لا تعني أن المقاول الرئيسي يبحث عن باطن. إذا لم تثبت العلاقة، يكتب «غير معلوم».

## سياسة المنتجات الرقمية

لا تعيد بيع قوالب أو ملفات من أطراف أخرى دون ترخيص، ولا تضف شعارات جهات حكومية توحي بالاعتماد. ملفات العينة المرفقة من إنشاء هذا المشروع، وتتضمن صيغًا عملية، لكنها قوالب إدارية تحتاج مراجعة محاسب/مهندس وتحديث وفق المعاملة قبل الاستخدام المهني. لا توجد أسعار مواد حقيقية فيها.

## الاستضافة والبنية في الإنتاج

ينبغي أن تكون **مشروعًا تقنيًا مستقلًا** عن مستودع GHAZIBOT المالي، مع إمكانية إعادة استخدام المهارات البرمجية لا كوده التجاري وبياناته دون داعٍ.

مقترح مرحلي، لا يعتمد على Claude أثناء التشغيل:
- Frontend: Next.js / React، عربـي RTL، تجربة جوال أولًا.
- Backend: FastAPI أو API Node.js مستقلة مع طبقات صلاحيات ومنع IDOR.
- Database: PostgreSQL ونسخ احتياطية واستعادة مختبرة.
- Storage: تخزين خاص للملفات مع روابط تنزيل موقعة ومحددة المدة.
- Search: فهرسة PostgreSQL في البداية، لا حاجة لمحرك مدفوع مبكرًا.
- Jobs: إدخال وتحديث من مصادر مصرح بها أو من مراجعة يدوية، مع قنوات اعتماد ومراجعة.
- Payment: دراسة بوابة سعودية تدعم مدى والبطاقات والاشتراكات، مثل Moyasar، مع Webhooks موقعة واختبار sandbox.
- Customer messaging: بريد تفعيل واستعادة، وتنبيهات بريد/Telegram اختيارية.
- Infrastructure: خطة استضافة تسمح بالأنشطة التجارية، HTTPS، سجل أحداث، مراقبة الأخطاء.

## مراحل التوسع

**P0 — Validate:** 20 مقابلة مع مقاولين (الجبس، البلاط، الدهانات، الأسقف، الأبواب، الصيانة)؛ 30 فرصة ذات مصدر؛ 5 شركات تنشر احتياجات الباطن مباشرة أو تسمح بالتواصل.

**P1 — Paid-pilot ready:** حسابات، فصل مستخدمين، لوحة مراجعة الفرص، إضافة ومصدر وتاريخ تحقق، تنزيلات متجر محمية، خصوصية، فواتير sandbox، اختبارات.

**P2 — Beta:** أول 10 عملاء تجريبيين، 5 منتجات رقمية قابلة للبيع، قياس زمن التحقق ومعدل التواصل الصحيح، عمليات الاسترجاع والدعم.

**P3 — Scale:** مطابقة أعمق، تنبيهات مناطقية، نموذج نشر مشروع ومقاول باطن، بوابة شركات رئيسية، واجهات مصدر مرخصة.

## نموذج الإيرادات — فرضيات للاختبار

- الرادار الأساسي مجاني مع مصادر عامة محدودة.
- اشتراك مقاول: 199 ر.س شهريًا مقابل فلاتر/قائمة عمل/معلومات موثقة بحقوق نشر مناسبة.
- اشتراك محترف: 399 ر.س شهريًا مقابل تخصيص وتنبيهات وتقارير إضافية (لا تضمن وجود فرص).
- الملفات الرقمية: 79–399 ر.س للمنتج حسب فائدته، والتجربة الحالية متاحة مجانًا.
- خدمة اختيارية للشركات الرئيسية: نشر طلب مقاول باطن أو إعداد قائمة مرشحين، بعقود منفصلة وبشرط عدم تقاضي مبالغ على وعود فرص غير مثبتة.

كل الأسعار قبل اختبار الاستعداد للدفع وبدون حساب رسوم بوابة الدفع والاستضافة والضريبة ودعم العملاء.
