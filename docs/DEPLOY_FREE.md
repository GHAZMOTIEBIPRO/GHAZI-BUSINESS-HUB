# نشر مجاني خطوة بخطوة (رابط HTTPS عام دون تكلفة)

المكوّنات المجانية: **GitHub** (كود + CI + الجدولة) · **Neon** (PostgreSQL دائمة) · **Render** (الموقع) · **Brevo** (بريد عبر HTTPS API، 300 رسالة/يوم).
تحقق من صفحات الأسعار قبل التسجيل؛ الشروط قد تتغير.

> حدود المجاني: خادم Render ينام بعد ~15 دقيقة دون زيارات (أول زيارة بعدها ~دقيقة)، ويمنع منافذ SMTP؛ لذلك البريد عبر HTTPS API فقط.
> ساعات Render المجانية مشتركة بين خدمات مساحة العمل: مهمة التحديث تعمل كل ساعتين ليبقى الاستهلاك منخفضًا.

## 1) Neon — قاعدة البيانات
Console ← المشروع `proud-forest-70054174` ← فرع `production` ← **Connect** ← قاعدة `neondb` ← فعّل **Connection pooling** ← انسخ الرابط.
- الرابط المطلوب يحتوي `-pooler` في اسم الخادم وينتهي بـ `sslmode=require` (الاتصال مشفّر).
- التطبيق يعطّل التحضير المسبق للاستعلامات تلقائيًا ليتوافق مع الـ pooler (`hub/db.py`).

## 2) Render — الموقع
خطة الـ Blueprint (`render.yaml`، خطة free) ← عند الاعتماد أدخل في الخانات السرية:
- `HUB_DATABASE_URL` = رابط Neon من الخطوة 1. **إلزامي**: في وضع staging يرفض التطبيق العمل دونه، فلا يعمل على SQLite مؤقتة تفقد البيانات.
- `HUB_MAIL_API_KEY` و`HUB_MAIL_FROM` (اختياري الآن؛ انظر الخطوة 4).
- لا حاجة لـ `HUB_BASE_URL`: يقرأ التطبيق `RENDER_EXTERNAL_URL` الذي يضعه Render نفسه.
- `HUB_SECRET_KEY` و`HUB_JOBS_TOKEN` و`HUB_SETUP_TOKEN` تُولَّد تلقائيًا.

التحقق بعد النشر: افتح `https://<الرابط>/healthz` ويجب أن يظهر `"db":"postgresql"` و`"env":"staging"`.

## 3) حساب الإدارة الأول (مرة واحدة)
1. انسخ `HUB_SETUP_TOKEN` من لوحة Render (Environment) وافتح `https://<الرابط>/setup`.
2. أدخل الرمز وبريدًا **جديدًا** للإدارة (لا يمكن ترقية حساب موجود).
   - إن كان مزود البريد مضبوطًا: أكّد البريد من الرسالة.
   - إن لم يُضبط بعد: يُعتمد رمز الإعداد (المرئي في لوحتك فقط) إثباتًا، ويُسجَّل ذلك في سجل التدقيق.
3. فعّل **التحقق بخطوتين** (إلزامي لحسابات الإدارة)، ثم احذف `HUB_SETUP_TOKEN` من Render. الصفحة تُغلق تلقائيًا بعد أول مدير.

## 4) Brevo — البريد (لتأكيد حسابات المقاولين والتنبيهات)
brevo.com ← Senders ← أضف بريد المرسل وأكّده ← SMTP & API ← API Keys ← أنشئ مفتاحًا ← ضعه في `HUB_MAIL_API_KEY` في Render.
دون ذلك تبقى الرسائل في قائمة الانتظار (لا شيء يُفقد) ولا يستطيع المقاول تأكيد بريده.

## 5) الجدولة — تعمل دون أسرار
`radar-refresh` يعمل كل ساعتين من GitHub ويثبت هويته برمز OIDC قصير العمر يصدره GitHub نفسه
(`hub/oidc.py`: المستودع، الفرع main، ملف الـ workflow، نوع الحدث). لا حاجة لنسخ أي سر إلى GitHub.
- كل تشغيل يُسجَّل ويظهر في صفحة `/sources` (قسم «التحديث الآلي») وفي `/healthz` (`last_refresh_at`).
- لرابط مختلف: Variable باسم `HUB_BASE_URL` في إعدادات المستودع.

## 6) فحص القبول على الموقع الحقيقي
Actions ← `live-check` ← Run workflow. يفحص HTTPS وPostgreSQL والصفحات والترويسات الأمنية والتنزيل المجاني والمدفوع،
وينشئ حسابين مؤقتين لاختبار العزل ثم يحذفهما، ويلتقط صور الجوال والكمبيوتر (Artifact باسم `live-evidence`).

## ما يبقى مقفلًا عمدًا
- `HUB_ENV=staging`: الدفع التجريبي لفريق المنصة فقط؛ المدفوعات الحقيقية مغلقة.
- لا بيانات تجريبية على الرابط العام؛ الرادار فارغ بصدق حتى تُدخل فرص موثقة.
- أوصاف الفرص من مصادر غير مرخّصة لا تُعرض؛ الرابط والحقائق فقط.
- ملفات Excel المدفوعة: انظر `docs/PAID_FILES_RISK.md`.
