# أرشيف المناقصات والترسيات (Procurement Archive)

كل ما في الأرشيف **خاص** (`private_staging` ثم `archive_private`) حتى يُتحقق من حقوق إعادة الاستخدام لمصدره.
لا يوجد في هذا الإصدار أي مسار يجعل سجلًا عامًا. المصادر وحقوقها: `docs/SOURCES_MATRIX.md`.

## القواعد المطبقة في الكود
- **لا فائز من أقل عرض.** الترسية تُنشأ فقط إذا كانت حالة المنافسة «تمت الترسية» **و** اسم الفائز منشور.
  ترتيب الأسعار (`price_rank_among_published`) معلومة وصفية عن العروض الظاهرة فقط.
- **لا أسماء متقدمين مخترعة.** يُخزَّن الاسم كما نُشر (`bidder_name_raw`)، و`bid_list_complete` صحيح فقط إذا
  طابق عدد الأسماء المنشورة عدد العروض المعلن.
- **لا دمج بالاسم.** الهوية بـ`name_key` (تطبيع آمن: NFKC، المسافات، التطويل، التشكيل). `fold_key`
  (ة/ه، أ/ا، ى/ي) يُستخدم **للتنبيه** فقط («أسماء متشابهة قد لا تكون كيانًا واحدًا»). كل شركة
  `name_only_unverified` حتى يُسجَّل رقم سجل تجاري أو رقم موحد.
- **دورة الحياة منفصلة:** `A_open` / `B_closed` / `C_awarded` / `D_subcontract_confirmed`.
  الفئة D لا تُشتق من أي ترسية؛ تدخل فقط بدليل ومراجعة بشرية.
- **الاصطناعي لا يختلط بالحقيقي:** `is_synthetic=true`، مرجع `SYN-`، أسماء تبدأ بـ«اصطناعي»، ومستبعد من البحث افتراضيًا.

## التنقيح اليدوي والأتمتة (`hub/archive/curation.py`)
- **تحديث دورة الحياة تلقائيًا** ضمن مهمة `radar-refresh` كل ساعتين:
  - المنافسة المفتوحة التي مضى موعدها المنشور تصبح `B_closed`. لا يُجلب أي شيء من مصدر خارجي.
  - كل تغيير يُسجَّل في `change_history`، والعدد يظهر في ملخص التشغيل (`archive_closed`).
  - فرص الباطن التي مضى موعد الرد عليها تُغلق (`subcontracts_closed`).
- **تسجيل الهوية** (مدير فقط + CSRF) من صفحة الشركة:
  - المطلوب: رقم سجل تجاري (10 أرقام) أو رقم موحد (10 أرقام يبدأ بـ 7)، مع رابط دليل `https`.
  - الأرقام العربية مقبولة.
  - لا يُستبدل رقم متحقق منه برقم آخر.
- **الدمج بنفس الرقم فقط:**
  - إذا أُدخل رقم مسجل لكيان آخر، تعرض الصفحة التعارض ولا تدمج تلقائيًا.
  - الدمج يتطلب إعادة إدخال الرقم نفسه المتحقق منه على الكيان الهدف. سجلان برقمين مختلفين لا يُدمجان أبدًا.
  - الدمج ينقل العروض والترسيات والأسماء البديلة ويسجّل كل نقل، والزر «تراجع عن الدمج» يعيدها كما كانت.
  - الاستيرادات اللاحقة للاسم المدموج تُربط بالكيان الباقي.
  - `rollback` لدفعة لا يحذف شركة متحقق منها أو مدموجة.
- **فرص الباطن المؤكدة (D)** في `/admin/archive/subcontracts`:
  - تُدخل يدويًا مع نوع الدليل ورابط `https`.
  - تبقى «بانتظار مراجعة شخص ثانٍ» حتى يؤكدها موظف غير الذي أدخلها، وعدّاد D في الأرشيف يحسب المؤكدة المفتوحة فقط.
  - لا تُنشأ أبدًا من منافسة أو ترسية. `related_tender_id` للسياق فقط.

## ملفات البيانات المفتوحة الرسمية (XLSX/CSV) — `hub/archive/open_data.py`
ملف الجهة كما نُشر (مثل «منافسات وعقود وزارة الصحة 2020–2023» أو «بيانات المنافسات» من مكتبة اعتماد) يُستورد مباشرة:
```
python -m hub.archive.cli import moh.xlsx --publisher "وزارة الصحة (البيانات المفتوحة)" \
    --source saudi_open_data --source-url https://... --validate      # ثم --staging
```
أو من `/admin/archive/import`: الملف + المصدر + الجهة المالكة + رابط مجموعة البيانات.
- تُطابق الأعمدة بالمرادفات العربية والإنجليزية: رقم المنافسة أو العقد، الاسم، الجهة، المدينة، التواريخ، اسم
  المورد أو المتعاقد، القيمة.
- تواريخ Excel وd/m/yyyy تتحول إلى ISO. التاريخ الهجري يبقى كما نُشر مع تحذير.
- CSV بترميز UTF-8 أو Windows-1256.
- قائمة عقود فيها اسم مورد = ترسية منشورة. قائمة منافسات بلا عمود مورد لا تُنشئ فائزًا أبدًا.
- الصف بلا مورد لا يُستنتج له شيء.
- أعمدة غير معروفة: يُرفض الملف مع عرض العناوين الموجودة.
- كل القواعد الأخرى سارية: خاص، `rollback` بالدفعة، إعادة الرفع لا تكرر.

## تحليلات السوق والتصدير (للموظفين فقط)
- `/admin/archive/insights`: أعداد على عينة الأرشيف بحسب المدينة والتخصص والسنة والجهة، مع اختصارات لمدن الأولوية
  (ينبع الصناعية، ينبع، جدة، الرياض).
  - تعرض: عدد المنافسات بحسب التصنيف، أقل/وسيط/أعلى قيمة ترسية منشورة، الشركات الأكثر ظهورًا (مشاركات ظاهرة
    وترسيات منشورة)، الجهات الطارحة، المدن.
  - **أعداد فقط**: لا نسب فوز ولا حصص سوقية، والصفحة تذكر عدد المنافسات المرساة التي قائمة متقدميها غير مكتملة.
- `/admin/archive/export.csv`: تنزيل نتائج البحث الحالي (حتى 5000 صف).
  - السطر الأول تنبيه بأن الملف خاص وغير مرخص لإعادة النشر.
  - كل تنزيل يُسجَّل في `audit_logs` (`archive.export_csv`).
  - الخلايا التي تبدأ بـ `= + - @` تُحيَّد حتى لا تُقرأ كصيغة في Excel.

## أمر الاستيراد
```
python -m hub.archive.cli import PACKAGE.zip --dry-run          # قراءة وتحقق فقط، بلا قاعدة
python -m hub.archive.cli import PACKAGE.zip --validate         # مقارنة بما في الأرشيف (قراءة فقط)
python -m hub.archive.cli import PACKAGE.zip --staging --report out.json   # كتابة مجزأة قابلة للاستئناف
python -m hub.archive.cli import PACKAGE.zip --resume BATCH_ID  # استئناف دفعة انقطعت (يرفض ملفًا مختلفًا)
python -m hub.archive.cli commit BATCH_ID                       # نقل إلى الأرشيف الخاص (يبقى غير عام)
python -m hub.archive.cli rollback BATCH_ID                     # حذف ما أنشأته الدفعة واسترجاع القيم المعدلة
python -m hub.archive.cli migrate                               # alembic upgrade head
```
- كل جزء (chunk) يُكتب مع نقطة الاستئناف في معاملة واحدة.
- إعادة تشغيل الحزمة نفسها لا تكرر شيئًا: المفتاح `official_reference`، وأي تعديل يُسجَّل في `change_history`.
- لا تُمسح قيمة معروفة بقيمة فارغة.
- يمكن الرفع أيضًا من `/admin/archive/import` (مدير فقط + CSRF).

## قبل أي استيراد إلى قاعدة الإنتاج (Neon)
1. دمج PR #1 ثم هذا الفرع بعد موافقة المالك.
2. نسخة احتياطية: `python scripts/backup.py` (أو Neon branch)، ثم **اختبار استعادة** على قاعدة منفصلة.
3. `python -m hub.archive.cli migrate`. التطبيق يشغّله عند الإقلاع أيضًا.
4. `--validate` ثم `--staging`، ثم مراجعة التقرير (`/admin/archive/batches/ID`). `commit` بعد المراجعة فقط.
5. التراجع: `rollback BATCH_ID`؛ وللمخطط: `alembic downgrade base`، وهو يحذف جداول الأرشيف فقط.

الإعداد على Render: **Dashboard → خدمة ghazi-business-hub → Environment → `HUB_DATABASE_URL`** (رابط Neon المُجمَّع `-pooler` مع `sslmode=require`)
ويُدخله المالك هناك ولا يُلصق في المحادثة. ثم يُفحص `/healthz` حتى يعرض `"db":"postgresql"`.
